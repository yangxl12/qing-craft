# 泥火青花 UI 与交互规范及改造实施计划

> 文档状态：改造基线与实施规范
>
> 编制日期：2026-08-28
>
> 适用范围：首页、创作台七道工序、作品集、设置页、成品页及后续新增页面
>
> 本轮边界：本文只建立规范与实施计划，不修改现有业务页面、作品数据结构或视觉资源。

## 1. 结论摘要

当前项目已经具备较强的单页表现力：首页有“月窗天青”的品牌画面，作品集与设置页有宣纸、墨色、朱砂语汇，创作台与成品页有沉浸式工坊空间。问题不是“没有设计”，而是这些设计尚未被同一套规则管理，最终形成了三套并行的视觉方言：

1. 首页偏冷蓝、现代、明亮；
2. 作品集与设置页偏暖纸色、朱砂、传统陈列；
3. 创作台与成品页偏暗青写实工坊、玻璃拟态控件。

页面内部也存在明显的设计债务：全局 Token 被页面局部色值覆盖，同名导航和按钮重复实现；`pages/studio/studio.wxss` 已增长到 4523 行，存在多轮覆盖式规则；部分文字只有 `12–19rpx`，部分操作热区只有 `50–62rpx`；复杂图片上的半透明面板对比度不稳定；成品页在当前 `362×783` 模拟器中出现底部按钮横向溢出，分享按钮被裁切。

本次统一改造采用以下总方向：

- 设计主题：**雨过天青，窑火一瞬**。
- 产品主体：一款让普通用户在手机上完成陶瓷创作的微信小程序。
- 页面唯一主角：用户正在制作或已经完成的器物，界面只负责托举、引导和反馈。
- 视觉气质：简洁精致、温润安静、清晰克制；有宋代审美的留白、比例和材质感，但不做符号堆砌或仿古陈设复刻。
- 设计签名：**釉痕线**。使用一条由松烟墨过渡到汝窑天青的细线表达选中、进度和工序流转，只在关键节点出现，替代重复的印章、粗下划线和高饱和装饰。
- 实施方式：先建立 Token 和基础控件，再逐页迁移；先解决可读性、溢出、误导设置和触控尺寸，再调整风格，不进行一次性大重写。

## 2. 当前实现审计

本次检查覆盖：

- `app.json`、`app.wxss`；
- `pages/index`、`pages/gallery`、`pages/settings`、`pages/studio`、`pages/result` 的 WXML、WXSS 与交互绑定；
- 设置项在 TypeScript 中的实际消费情况；

### 2.2 已有优势

1. 产品题材明确，器物、窑火、天青釉、月窗和工坊都能为设计语言提供真实依据。
2. 首页主视觉与品牌名称匹配，图片质量和构图可继续复用。
3. 作品集、设置页已经形成相近的信息页面结构，可低成本统一为共享页面壳。
4. 创作台已具备安全区、WebGL 兜底、撤销重做、保存状态、减少动态和触觉反馈等良好基础。
5. 装饰页已经实现菜单与真实装饰图层同步、可撤销复制、两指观察和全屏手势约束，后续视觉重构不得破坏这些行为。
6. 成品页与装饰页共享工坊背景，具备从创作到陈列的空间连续性。

### 2.3 核心问题

#### A. 色彩与页面气质分裂

- `app.wxss` 定义了纸白、灰绿、天青、陶土、窑火和钴蓝，但首页继续直接使用 `#183e62` 等冷蓝色；作品集和设置页又重新定义暖纸、朱砂、玉色；创作台和成品页大量使用独立暗色及透明色。
- 页面局部变量覆盖全局同名变量，导致 `--paper`、`--ink`、`--celadon-deep` 在不同页面并非同一含义。
- 宋代审美被简化为“宋体 + 宣纸 + 印章”，而材质、比例、留白和克制程度没有形成全局规则。

#### B. 字体层级过多且小字过小

- 信息页中存在 `17–21rpx` 元信息；创作台中存在 `12–19rpx` 的提示、状态和按钮文字。
- 中文标题大量使用 `0.14–0.26em` 字距，短标题尚可，长标题会显得松散和装饰化。
- 同一种信息角色在不同页面使用不同字号，例如导航标题、辅助说明、底部操作文字没有统一层级。
- 宋体有时承担按钮和微型状态文字，不利于小尺寸屏幕识别。

#### C. 图标来源和视觉重量不统一

- 当前同时使用 Unicode 箭头、数学符号、全屏符号、问号、临时字符图标和 CSS 绘制图标。
- 装饰侧栏的 `✦`、`◫`、`❋`、`⌁` 只是临时符号，无法稳定表达分类。
- `‹`、`↶`、`↷`、`↗`、`⛶`、`⇅` 等字符受系统字体影响，线宽、基线和视觉尺寸不一致。
- 有些图标控件只有视觉符号；现有代码主要使用 Web 风格的 `role`，尚未统一核对目标基础库要求的 `aria-role`、状态属性和禁用语义。

#### D. 布局、触控和响应式存在风险

- 首页顶部入口高 `50rpx`，作品集和设置页返回按钮为 `56rpx`，创作台多处控件最终被覆盖为 `56–62rpx`，低于舒适触控目标。
- 成品页底部使用 `1.35fr 1fr 96rpx`，但未用 `minmax(0, …)` 消除内容最小宽度；当前模拟器中第三个按钮被挤出屏幕。
- 创作台通过多轮样式覆盖缩小控件以塞入画面，降低了可读性和可点性。
- 复杂背景与功能面板同时承担视觉焦点，装饰页展开菜单时器物、背景、面板、标签和按钮相互竞争。

#### E. 圆角、阴影和材质缺少统一约束

- 全局 `button` 默认使用 `999rpx`，造成大量按钮自动胶囊化。
- 项目中出现 40 种创作台圆角值，同一层级控件没有稳定的轮廓语言。
- 卡片、浮层、按钮和工坊控件分别使用不同的描边、阴影和透明度，精致感依赖局部调参，维护成本高。
- 宣纸纹理、渐变、玻璃拟态和真实背景图同时出现，缺少“何时使用材质、何时保持纯净”的边界。

#### F. 对比度与可访问性不稳定

- 作品集与设置页的 `#8B8574` 在 `#F5F1E6` 上对比度约为 `3.26:1`，不适合作为小号正文。
- 装饰页的浅色半透明菜单直接叠在明暗变化较大的背景图上，截图中标签和未选项明显发灰。
- 部分选中态主要依赖颜色，部分禁用态只降低透明度但没有 `aria-disabled`。
- 作品集和设置页大量可点击 `view` 缺少按钮、单选或标签页角色；长按进入整理模式也缺少等价的显式入口。

#### G. 交互承诺与实际能力不一致

- `reduceMotion`、`quality`、`haptics` 已被业务代码消费。
- “环境声音”当前只保存设置，没有声音引擎或播放逻辑。
- “引导强度”当前只保存设置，没有用于决定创作台提示策略。
- 设置页因此向用户展示了两个尚未真正生效的选项，应在实施早期解决。

### 2.4 先行问题分级

| 等级 | 问题 | 影响 | 首选处理 |

## 3. 设计北极星

### 3.1 主题与对象

- 具体对象：移动端陶瓷创作工坊。
- 主要用户：对陶瓷和传统文化有兴趣、但不熟悉专业制陶术语的普通用户。
- 核心任务：让用户始终清楚“当前在做什么、器物发生了什么、下一步会去哪里”。
- 视觉主角：器物本身；界面不与器物争夺注意力。

### 3.2 设计关键词

| 保留 | 避免 |
| --- | --- |
| 天青、月白、松烟、窑火、留白、薄釉、温润 | 满屏米黄、堆叠印章、祥云边框、仿古纹样铺底 |
| 真实材质作为场景，规则化控件作为工具 | 每个控件都做玻璃拟态或厚重拟物 |
| 宋体负责气质，系统无衬线负责操作 | 所有文本都用宋体，微型文字强行拉大字距 |
| 一处有记忆点，其余安静 | 每个区块都需要装饰性标题、分隔线或渐变 |
| 工序动作清楚、状态反馈直接 | 诗意文案替代真实操作名称 |

### 3.3 标志性视觉：釉痕线

“釉痕线”是一条 `2–4rpx` 的低饱和渐变细线，表现釉色在器物边缘积聚的感觉，用于：

- 当前页签或分段选项；
- 七道工序的已完成与当前进度；
- 重要卡片的选中边；
- 页面或面板进入完成状态时的一次短促扫光。

限制：

- 同一屏最多出现两条显著釉痕线；
- 不用于普通分隔线；
- 不与朱砂印章同时抢夺同一区域；
- 减少动态模式下只保留静态线，不播放扫光。

### 3.4 双场景但同语言

项目允许存在两种环境，不要求所有页面使用同一种背景：

1. **月白内容场景**：首页、作品集、设置、信息面板、导出预览。使用浅色底、清晰墨色文字、克制天青交互色。
2. **松烟工坊场景**：创作台和成品展台。使用暗色空间和真实图片，但控件仍沿用同一字号、圆角、描边、图标和状态语义。

深浅场景的差别是环境亮度，不是组件体系。一个“返回”“选中”“危险操作”在两种场景中应保持相同结构和反馈。

## 4. 色彩体系

### 4.1 品牌与辅助色

| Token | 名称 | 色值 | 使用场景 |
| --- | --- | --- | --- |
| `--color-celadon-100` | 薄釉 | `#DCE7E2` | 轻选中底、信息提示底 |
| `--color-celadon-300` | 汝釉浅青 | `#9CB9AC` | 深色场景辅助文字、釉痕高光 |
| `--color-celadon-500` | 雨过天青 | `#648B7D` | 开关、图形、较大面积选中状态 |
| `--color-celadon-700` | 深天青 | `#365A51` | 主按钮、正文链接、焦点描边 |
| `--color-cobalt` | 黛青 | `#35657A` | 信息状态、少量数据与冷色辅助 |

使用规则：

- 主交互统一使用深天青，不再让首页用钴蓝、内容页用朱砂、创作台用另一套绿色分别承担主按钮。
- 朱砂面积建议不超过单屏可见面积的 5%，用于印记、危险提示的小型标识或文化性强调。
- 窑火只在烧制流程和警告语义中出现，不能变成通用强调色。
- 天青色不直接用于浅底小字，必须使用对比足够的 `celadon-700`。

### 4.3 功能色

| Token | 色值 | 语义 | 规则 |
| --- | --- | --- | --- |
| `--color-success` | `#3F745B` | 保存成功、完成、可用 | 不等同于“当前选中” |

### 4.4 语义 Token 示例

实施时页面只引用语义 Token，不直接引用色阶：

```css
page {
  --ui-bg: #f2f4ef;
  --ui-surface: #fafbf7;
  --ui-text: #202923;
  --ui-text-secondary: #53615a;
  --ui-border: #cbd3cd;
  --ui-action: #365a51;
  --ui-action-text: #f8faf6;
  --ui-accent: #984b42;
  --ui-danger: #9c3f38;
}

.tone-dark {
  --ui-bg: #16211e;
  --ui-surface: #22322d;
  --ui-text: #f2f4ee;
  --ui-text-secondary: #c4cec8;
  --ui-border: rgba(196, 206, 200, 0.24);
  --ui-action: #9cb9ac;
  --ui-action-text: #16211e;
}
```

迁移期可让旧变量指向新 Token，例如 `--paper: var(--ui-bg)`，待全部页面迁移后删除旧别名，禁止继续让页面重新定义同名变量。

### 4.5 对比度基线

| 前景 / 背景 | 对比度 | 结论 |
| --- | ---: | --- |
| `#202923` / `#F2F4EF` | `13.52:1` | 主文字 AAA |
| `#53615A` / `#F2F4EF` | `5.88:1` | 小正文 AA |
| `#657269` / `#F2F4EF` | `4.55:1` | 普通文字 AA 下限 |
| `#F8FAF6` / `#365A51` | `7.30:1` | 主按钮文字 AAA |
| `#984B42` / `#F2F4EF` | `5.54:1` | 朱砂小字 AA |
| `#F2F4EE` / `#16211E` | `14.92:1` | 深色主文字 AAA |
| `#C4CEC8` / `#16211E` | `10.24:1` | 深色辅助文字 AAA |

验收规则：

- 普通文字不低于 `4.5:1`；大号文字不低于 `3:1`；图标、边界和关键非文本控件不低于 `3:1`。
- 图片背景不能只依赖文字阴影保证阅读。文字区必须有稳定的渐变遮罩、实色底或合成后仍通过对比度检查的高不透明面板。
- 半透明控件应按最亮和最暗背景分别取样，不能只检查 CSS 前景色与理论底色。
- 禁用控件虽不受普通文字对比度要求约束，仍需保持可辨认，并同时提供不可操作的语义状态。

## 5. 字体规范

### 5.1 字体角色

| 角色 | 字体栈 | 使用范围 |
| --- | --- | --- |
| 展示字体 | `"Songti SC", "STSong", "SimSun", serif` | 品牌名、页面主标题、器物名称、少量诗性标题 |
| 正文字体 | `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif` | 正文、按钮、菜单、设置、提示、表单 |
| 数据字体 | `SFMono-Regular, Menlo, Consolas, monospace` | 温度、毫米值、进度等短数字，不用于中文 |

首轮不引入网络字体或新的字体文件，避免授权、包体和加载闪烁问题。宋体只负责气质，不承担所有操作文字。

### 5.2 字号层级

| Token | 字号 / 行高 | 字重 | 典型用途 |
| --- | --- | ---: | --- |
| `type-display` | `52 / 68rpx` | 500 | 首页主张、成品名称 |
| `type-h1` | `44 / 60rpx` | 500 | 页面主标题 |
| `type-h2` | `36 / 52rpx` | 500 | 面板标题、重要空状态 |
| `type-h3` | `32 / 46rpx` | 600 | 卡片标题、设置分组核心标题 |
| `type-body-lg` | `30 / 46rpx` | 400 | 强调正文、主要说明 |
| `type-body` | `28 / 42rpx` | 400 | 默认正文、按钮、菜单 |
| `type-body-sm` | `26 / 38rpx` | 400 | 次级说明、元信息 |
| `type-caption` | `24 / 34rpx` | 400/500 | 辅助标签、时间、计数 |
| `type-micro` | `22 / 30rpx` | 500 | 角标和极短状态，不承载关键操作 |

规则：

- 关键操作文字不得小于 `28rpx`；普通说明不得小于 `24rpx`。
- 创作台现有 `12–19rpx` 文本必须通过重排而不是继续缩小解决。
- 中文正文不额外增加字距；中文标题建议 `0–0.08em`；仅短印章字可到 `0.12em`。
- 英文眉题可使用大写与 `0.12em` 字距，但它只能是辅助信息，不能比中文主信息更醒目。
- 只使用 400、500、600 三档字重。避免在宋体上大量使用 700 造成伪粗体和笔画粘连。
- 单行操作名称优先使用明确动词，例如“开始制坯”“继续创作”“生成作品图”，避免仅用“开始”“完成”等脱离上下文的词。

## 6. 图标规范

### 6.1 图标来源

建立一套本地、单色、描边式图标资产，不使用在线 Iconfont，不混用 Emoji，不继续把随机 Unicode 字符当正式图标。首轮只制作项目实际需要的约 20–24 枚图标：

- 导航：返回、关闭、更多、帮助；
- 历史：撤销、重做；
- 视图：全屏、退出全屏、视角回正、展开、收起；
- 编辑：删除、复制、翻转、水平缩放、垂直缩放；
- 状态：勾选、信息、警告、成功、失败、保存中；
- 业务：器形、泥料、纹样、题款、彩绘、窑火、分享、下载。

优先使用本地 SVG/PNG 资产并通过轻量 `ui-icon` 包装统一尺寸和无障碍属性。若开发者工具对目标基础库的 SVG 表现不稳定，再批量导出 2× PNG，不在各页面手绘不同版本。

### 6.2 绘制规则

- 基准网格：`24×24`。
- 标准描边：`1.75`，圆头、圆角连接。
- 标准视觉尺寸：小 `32rpx`、常规 `40rpx`、强调 `48rpx`。
- 图标容器推荐 `88×88rpx`；创作台密集区域最低 `80×80rpx`。
- 填充图标只用于明确状态，例如选中勾、错误或保存成功；普通操作使用描边图标。
- 同一按钮不能同时依赖字符箭头和 SVG 图标。
- 图标颜色继承当前语义状态，不为每枚图标单独硬编码颜色。

### 6.3 图标与文字

- 主流程、危险操作、不可逆操作必须保留可见文字；图标只辅助识别。
- 高频且空间受限的工具可使用纯图标；优先采用原生 `button`，必须使用自定义 `view` 时，再按目标基础库验证结果设置 `aria-role="button"`、明确 `aria-label`、选中/禁用语义和稳定点击热区。
- 导航返回、撤销、重做、删除不能仅靠方向或颜色表达。
- 图标按钮按下时反馈作用于容器，不单独缩放图标，避免视觉跳动。

## 7. 布局与间距

### 7.1 基础栅格

- 手机页面使用 4 列流式栅格。
- 常规页面左右安全边距 `32rpx`；窄屏可降至 `24rpx`，不得再小。
- 列间距 `16rpx`，较松内容区可用 `24rpx`。
- 全宽背景可越过栅格，文字、控件和可点区域必须回到安全边距内。
- 创作台装饰菜单保留左侧材料库、右侧当前图层约 `3:2` 的目标比例，使用 `minmax(0, 3fr) minmax(0, 2fr)`，避免内容撑破列宽。

### 7.2 间距刻度

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `space-1` | `4rpx` | 仅视觉微调 |
| `space-2` | `8rpx` | 图标内部、紧密元素 |
| `space-3` | `12rpx` | 标签内部 |
| `space-4` | `16rpx` | 控件间、Grid Gap |
| `space-6` | `24rpx` | 卡片内边距、小区块间距 |
| `space-8` | `32rpx` | 页面边距、标准卡片内边距 |
| `space-10` | `40rpx` | 标题与内容 |
| `space-12` | `48rpx` | 区块间距 |
| `space-16` | `64rpx` | 页面大段留白 |

不得继续新增任意间距值，除非来自安全区、胶囊位置、WebGL 接触线或器物视觉尺度等真实运行时约束。

### 7.3 页面结构

内容页面统一为：

```text
系统安全区
└─ 自定义导航（固定高度、同一返回热区）
   └─ 页面题头（标题 + 一句说明；印章为可选，不是默认）
      └─ 主内容区（卡片/列表/网格）
         └─ 底部操作区（需要时固定，并包含底部安全区）
```

沉浸创作页面统一为：

```text
背景环境层（不响应事件）
└─ 安全区与工序导航层
   └─ 器物舞台 / WebGL 层
      └─ 上下文工具层
         └─ 工序抽屉与底部主操作层
```

层级要求：背景不响应触摸；舞台只处理器物和相机手势；工具层阻止事件穿透；抽屉展开/收起时必须重新计算画布尺寸，并保持器物形状、比例和视觉尺度，只调整居中和相机距离。

### 7.4 响应式断点

验收至少覆盖：

- 短窄屏：`320×568`；
- 常规屏：`375×812`；
- 宽长屏：`430×932`。

响应式优先顺序：

1. 保住系统安全区与主操作；
2. 保住器物完整可见和触控热区；
3. 收紧区块间距；
4. 折叠辅助说明或次级工具；
5. 最后才调整装饰性元素。

不得通过把正文缩到 `24rpx` 以下或把按钮缩到 `80rpx` 以下来适配短屏。

## 8. 圆角、边框、阴影与材质

### 8.1 圆角

| Token | 数值 | 使用场景 |
| --- | ---: | --- |
| `radius-xs` | `8rpx` | 印记、微型角标、色块 |
| `radius-sm` | `16rpx` | 标签、小控件、分段项 |
| `radius-md` | `24rpx` | 卡片、输入框、常规按钮 |
| `radius-lg` | `32rpx` | 抽屉、浮层、大型面板 |
| `radius-hero` | `40rpx` | 首页框景等唯一主视觉 |
| `radius-full` | `999rpx/50%` | 圆形图标、状态胶囊，禁止作为按钮默认值 |

规则：

- 删除全局 `button { border-radius: 999rpx; }`，每类控件显式选择语义圆角。
- 同一容器内部的子控件圆角比父容器小一个等级。
- 非对称圆角只保留给首页“月窗框景”等标志性构图，不扩散到普通卡片。

### 8.2 边框与阴影

- 常规边框：`1rpx solid var(--ui-border)`。
- 选中边框：`2rpx solid var(--ui-action)`，同时增加浅底或勾选图标，不能只变色。
- 分隔线优先使用边框色，不额外加阴影。
- 阴影分三级：
  - `elevation-1`：卡片，柔和且接近表面；
  - `elevation-2`：浮动工具、固定操作栏；
  - `elevation-3`：模态抽屉和覆盖层。
- 单个组件最多一层外阴影加一层内高光，删除多层堆叠的装饰性阴影。

### 8.3 材质与图片

- 真实图片只用于首页框景、制坯/装饰工坊和窑烧等确有空间语义的场景。
- 普通内容页面只允许一层极轻纹理，不给每张卡片单独叠纸纹。
- 玻璃拟态只用于沉浸式场景中的临时工具，不用于长正文、设置表单和重要确认。
- 复杂背景上的功能面板优先使用 `0.88–0.94` 的深色或浅色表面；`backdrop-filter` 是增强，不是可读性前提。
- 印章只用于品牌、收藏、署名等有真实文化语义的位置，不作为每个分组的默认标题图标。

## 9. 基础组件与状态规范

### 9.1 组件层级

首轮建立以下稳定基础，不一次性组件化所有页面：

1. `ui-icon`：统一图标源、尺寸和可访问名称；
2. `app-nav`：统一安全区、返回热区、标题、明暗主题和胶囊避让；
3. 按钮样式类：主按钮、次按钮、文字按钮、图标按钮、危险按钮；
4. 选择样式类：标签页、分段选择、单选、多选；
5. 表面样式类：卡片、工具浮层、底部操作区、模态抽屉；
6. 状态样式类：加载、空、错误、禁用、保存中、保存成功。

只有在三个及以上页面重复、且行为已经稳定时，才把卡片、空状态等进一步抽成 WXML 组件，避免为了“统一”引入难以维护的万能组件。

### 9.2 交互状态矩阵

| 状态 | 视觉 | 行为 | 语义/反馈 |
| --- | --- | --- | --- |
| 默认 | 清晰文本、稳定边界 | 可点击 | 正确角色和名称 |
| 按下 | 容器缩放到 `0.98` 或轻微下移，背景加深 | `120ms` 内响应 | 可选轻触反馈，不改变标签 |
| 选中 | 背景、边框和勾选/状态图标至少两种线索 | 再点按按组件语义取消或保持 | 使用目标基础库实际支持的 ARIA 状态；读屏标签同时朗读“已选中/未选中”作兜底 |
| 禁用 | 降低层级但保持可辨认 | 事件处理器必须守卫，不执行副作用 | `aria-disabled="true"` |
| 加载 | 保留按钮宽度，显示进度图标和进行时文案 | 禁止重复提交 | `loading` 或明确状态文案 |
| 成功 | 短暂状态图标/Toast，必要时轻震 | 完成后进入下一稳定状态 | 文案与动作名称一致 |
| 错误 | 危险色 + 原因 + 恢复动作 | 不清空用户输入 | 不使用“失败了”这类模糊文案 |

### 9.3 按钮层级

- 一屏同一操作区最多一个视觉主按钮。
- 次按钮不与主按钮使用相同填充强度。
- 危险按钮默认不放在主操作位置；确认弹窗中危险动作放在明确的危险位并写完整结果。
- 图标按钮必须有稳定外框或热区，不使用裸字符漂浮在背景上。
- 加载中的“生成作品图”应改为“正在生成”，成功提示为“作品图已生成”，用词保持一致。

## 10. 交互、动效与触觉

### 10.1 动效 Token

| Token | 时长 | 用途 |
| --- | ---: | --- |
| `motion-instant` | `80ms` | 极小状态切换，不用于位移 |
| `motion-fast` | `120ms` | 按压、图标反馈 |
| `motion-base` | `180ms` | 选中、展开局部控件 |
| `motion-overlay` | `280ms` | 抽屉、信息面板、模态层 |
| `motion-stage` | `420ms` | 工序完成与场景交接，只保留一处主叙事动效 |

推荐缓动：

- 进入/展开：`cubic-bezier(0.2, 0, 0, 1)`；
- 退出/收起：`cubic-bezier(0.4, 0, 1, 1)`；
- 直接操控：不加过渡，元素必须跟手。

原则：

- 优先动画 `transform` 和 `opacity`，避免持续触发布局和重绘。
- 一次操作只安排一个主要运动。不要同时让按钮、背景、标题和器物各自播放入场。
- 除陶轮、窑火等具有业务含义的环境运动外，不使用无限循环装饰动画。
- 工序完成可播放一次约 `420ms` 的釉痕扫过和轻微器物定光，随后稳定进入下一页。

### 10.2 减少动态

现有设置只在创作台被消费。改造后应成为全局能力：

- 所有页面进入动画、抽屉位移动画、背景扫光和循环环境动画都读取同一设置；
- 同时尊重系统 `prefers-reduced-motion`（目标基础库支持时）；
- 减少动态不删除状态反馈，而是改为即时显隐、颜色和图标变化；
- 陶轮、窑火粒子、热浪和釉痕扫光停止；用户直接拖动的器物仍即时跟手。

### 10.3 触觉反馈

- 轻触：明确选中纹样、切换重要工具、吸附到边界；
- 中等：完成工序、确认删除、题款落印；
- 不反馈：普通导航、滚动、每一次加减缩放、连续拖动中的每一帧；
- 所有反馈尊重 `haptics` 设置；触觉不能替代视觉和文字反馈。

### 10.4 手势规则

- 单指拖动器物或纹样，只在当前模式明确允许时生效。
- 双指统一控制相机环看和缩放，不复用为纹样变换。
- 装饰全屏模式继续禁止单指移动纹样，只允许双指控制视角与缩放。
- 工具浮层拖动区域与折叠按钮分离，折叠按钮不能触发拖动。
- 长按只能作为快捷方式，不得成为唯一入口。作品集需要提供可见的“整理”入口，以覆盖辅助技术和不熟悉长按的用户。
- 抽屉开合、短屏重排和全屏切换不得改变器物几何比例；只允许调整相机、画布尺寸和居中参数。

### 10.5 反馈与文案

- 文案从用户动作出发：使用“开始制坯”“完成装饰”“保存到相册”，不使用内部模块名。
- 错误包含原因和下一步，例如“图片没有生成，请检查相册权限后重试”。
- 空状态提供下一动作，例如“还没有作品，开始制坯”。
- 保存状态统一为“保存中 / 已保存 / 保存失败，点此重试”，不只用颜色区分。
- Toast 用于短结果；需要选择或解释后果时使用 Modal/Sheet；持续任务使用按钮内加载或进度面板。
- 删除和返回丢失装饰等破坏性操作必须先确认，取消后作品数据、选择和历史均不发生变化。

## 11. 无障碍与可读性规范

1. 优先使用原生 `button`、`radio`、`checkbox` 等组件。必须使用可点击 `view` 时，按目标基础库实测统一为受支持的 `aria-role`、`aria-label` 和状态属性；不能直接假定浏览器中的全部 ARIA 角色都能在小程序读屏中生效。
2. 装饰性图片、纹理和分隔线标记 `aria-hidden="true"`。
3. 所有触控目标推荐至少 `88×88rpx`；创作台密集区域不得低于 `80×80rpx`，目标之间至少保留 `8rpx`。
4. 禁用按钮同时提供视觉状态、`aria-disabled` 和代码守卫。
5. 选中状态至少使用颜色之外的一种线索，例如边框、勾选、位置或文字。
6. 输入框必须有可访问名称、可见标签、错误说明和字符限制；占位符不能代替标签。
7. 模态层打开后背景不可操作；点击遮罩关闭必须有等价的明确关闭按钮。
8. 信息抽屉内容超出屏幕时内部滚动，底部主操作和安全区不遮挡最后一项。
9. 不把关键说明放在 `22rpx` 以下；不把低对比英文眉题作为唯一类别名称。
10. 自动检查不能替代真实辅助技术测试，至少使用微信读屏或系统读屏完成首页、创作、删除和导出主流程冒烟。

## 12. 目标样式与代码组织

建议采用以下最小结构，不引入第三方 UI 框架：

```text
styles/
├─ tokens.wxss            色彩、字体、间距、圆角、层级、动效 Token
├─ primitives.wxss        按钮、卡片、标签、状态、底部操作区
└─ utilities.wxss         安全区、可访问隐藏、截断等少量工具类

components/
├─ ui-icon/               本地图标统一出口
└─ app-nav/               安全区、胶囊避让、明暗导航

utils/
└─ ui-metrics.ts          统一 statusBar/navBar/capsulePad 计算

pages/studio/styles/
├─ base.wxss              舞台、顶栏、转盘、共享底栏
├─ shaping.wxss           制坯
├─ decoration.wxss        装饰与彩绘
├─ glazing.wxss           上釉
└─ firing.wxss            高温烧制与低温烤花
```

`app.wxss` 只负责导入全局样式与设置 `page` 默认值；`pages/studio/studio.wxss` 作为阶段样式入口。拆分时必须先确认微信开发者工具对 `@import`、主包/分包路径和上传包体的行为。

### 12.1 约束

- `core/` 保持作品模型、渲染和陶艺算法职责，不放 UI Token。
- 不为统一样式改变 `PotteryWork` schema。
- 釉色、泥料和纹样本身的业务色允许由数据驱动，不强行映射为界面功能色。
- 新增共享组件前先验证它确实被多个页面重复使用，避免万能组件和大量参数分支。
- 创作台拆样式时不顺带重写手势算法；现有行为测试和历史保存路径必须保持稳定。

## 13. 分页面改造方案

### 13.1 首页 `pages/index`

保留：月窗天青器物主图、品牌 Logo、器物为视觉中心、单次淡入。

改造：

1. 将冷蓝按钮和文字迁移到统一天青/松烟 Token，保留图片自身冷色，不再用另一套品牌蓝强化割裂。
2. 顶部“作品/设置”扩大热区到推荐尺寸；视觉图标可小，但可点容器不能小。
3. 主按钮改为“开始制坯”，草稿入口改为“继续创作”，无草稿入口改为“查看作品”。
4. 首页主视觉的非对称圆角作为全局唯一“月窗框景”签名，不复制到普通卡片。
5. 读取用户的减少动态设置；短屏优先缩短上下留白，不压缩按钮和标题字号。
6. 首页顶部品牌、胶囊按钮、入口和标题在 `320×568` 下不得互相挤压。

验收：首次进入 1 秒内能明确识别品牌、器物和主操作；主按钮对比度不低于 `7:1`；两枚顶部入口均可舒适点按。

### 13.2 作品集 `pages/gallery`

保留：两列作品网格、全部/草稿/已成筛选、多选整理和空状态。

改造：

1. 与设置页共用 `app-nav`、页面边距、题头和卡片 Token。
2. 朱砂“藏”印缩小为辅助标识，标题和内容成为主层级，避免印章与标题同时过重。
3. 筛选项改为标准标签页，釉痕线表示当前项；每项至少具备按钮语义、可访问名称和“已选中”状态，不假定目标基础库必然支持 Web 的 `tablist/tab` 完整角色模型。
4. 增加可见“整理”入口，长按只作为快捷方式。
5. 卡片最小点击高度、选中边框、勾选和禁用状态统一；元信息提升到 `24–26rpx`。
6. 删除操作按钮在 `selectedCount=0` 时真正禁用，并声明 `aria-disabled`。
7. 后续可选：保存轻量作品缩略图，真实反映器形、釉色和纹样；加载失败继续使用当前轮廓兜底。

验收：不用长按也能进入和退出整理；筛选与多选不只靠颜色表达；删除取消不改变选择和作品。

### 13.3 设置页 `pages/settings`

保留：声与动、引导强度、画质、隐私说明的产品结构，以及即时保存方式。

改造：

1. 统一页面壳、字号、卡片、分段控件和间距。
2. 引导强度和画质优先改用原生单选能力；若因视觉结构保留自定义 `view`，则使用目标基础库已验证的单选角色、状态属性和包含当前值的读屏标签。
3. `guidance` 真正接入创作台提示策略：
   - 轻松引导：首用、停滞和风险提示；
   - 仅必要提示：只展示错误和不可逆风险；
   - 自由创作：默认隐藏教学提示，但帮助入口始终可用。
4. 在声音系统未实现前隐藏“环境声音”，或显示为明确不可用且不可点击的预告；不能继续保存一个无效偏好。
5. `reduceMotion` 扩展为全局页面行为，而非只影响创作台。
6. 设置变更用行内短状态或轻触反馈确认，不为每次切换弹 Toast。

验收：页面展示的每一项都能观察到真实效果；读屏能理解分组、选项和值；重新进入页面后状态正确恢复。

### 13.4 创作台 `pages/studio`

创作台是本轮最大改造项。实施前先建立当前七道工序、菜单展开/收起、全屏、WebGL 兜底和短屏截图基线。

#### A. 样式治理

1. 按 `base/shaping/decoration/glazing/firing` 拆分 WXSS。
2. 清理无引用规则和多轮覆盖规则；当前 `.circle` 出现 6 组定义、`.topbar` 出现 3 组定义，必须收敛为基础规则加明确阶段变体。
3. 把约 603 个色值字面量迁移到语义 Token 或场景局部 Token；背景图片和 WebGL 材质色除外。
4. 建立组件尺寸表，禁止再通过尾部覆盖把 `88rpx` 热区缩回 `56rpx`。

#### B. 顶栏与工序导航

1. 统一“退出、回正、撤销、重做、帮助、全屏”图标和热区。
2. 通过分组或“更多”菜单减少同层拥挤，不以缩小控件解决空间问题。
3. 工序名称、`x/7` 与保存状态重新分层；保存状态不得小于 `24rpx`。
4. 使用釉痕线表现七道工序进度，当前工序有文字和位置双重提示。

#### C. 舞台与器物优先级

1. 保留现有真实背景，但降低面板背后的局部细节和亮度竞争。
2. 陶坯、转盘、提示和工具面板建立固定层级；工具面板不得覆盖器物主要编辑区域。
3. 抽屉开合、全屏和短屏重排继续调用视觉尺度保护路径，保持器物不变形、只居中。
4. 兜底器物与 WebGL 主路径使用相同的布局、状态和操作提示。

#### D. 制坯阶段

1. 将器形、泥料、壁厚、手势帮助按“高频直接操作 / 低频设置 / 临时帮助”重组。
2. 现有 `12–19rpx` 提示提升到规范字号；必要时折叠说明，不缩字。
3. 右侧手势示意只在首次或帮助打开时显示，避免长期占据器物旁空间。
4. 保持已有塑形、双指相机和视觉尺度行为；具体手势算法继续遵循 `docs/制坯页面优化调研与实现方案.md`，本规范只接管视觉、布局、反馈和可访问性。

#### E. 装饰与彩绘阶段

1. 左侧材料库与右侧当前图层继续保持真实数据同步，不退化为 UI 选中态。
2. 面板改为稳定语义表面：浅色方案使用足够不透明的瓷白，深色方案使用深釉面；不在复杂背景上直接叠低对比半透明文字。
3. 保留约 `3:2` 面板比例，确保列轨道 `minmax(0, …)`，短屏优先折叠辅助标题。
4. 临时字符侧栏换为正式业务图标和可见名称；空间不足时名称在选中项或顶部上下文中展示。
5. 调校工具统一图标、热区、选中、禁用和按下状态；危险删除与复制、缩放、翻转分组。
6. 被选图菜单的复制编号、图层选择、撤销和持久化行为全部保留。
7. 全屏继续禁用单指纹样移动，只允许双指视角与缩放。
8. 返回制坯继续二次确认；取消确认不得清空装饰效果。

#### F. 上釉与窑烧阶段

1. 釉样卡片统一为单选组件，名称、色样和勾选三重表达当前选择。
2. 窑烧保持唯一明显的环境动效，其他控件保持安静。
3. 温度、进度和火候采用数据字体与规范功能色，确保文字不叠在最亮火焰上。
4. “跳过”属于次级动作，不与烧制进度和主叙事争夺层级；减少动态时停止粒子、热浪和呼吸效果。

验收：七道工序在三档屏幕上均无控件遮挡、文字小于规范、热区不足或器物比例变化；装饰层、历史、保存、手势和全屏约束不回归。

### 13.5 成品页 `pages/result`

保留：工坊展台、器物主视图、作品信息抽屉、生成作品图、纪念海报和分享。

改造：

1. 先修复底部 Grid：常规宽度使用 `minmax(0, 1.35fr) minmax(0, 1fr) 88rpx` 并给按钮 `min-width: 0`；窄屏将主按钮独占一行，次按钮与分享在第二行。
2. 顶部标题和器名所在区域增加稳定遮罩，不只依赖文字阴影。
3. 三个导出动作分别管理加载和防重复提交状态；分享图标换为正式图标。
4. 信息抽屉增加明确关闭按钮、内部滚动、底部安全区和打开/关闭动效；遮罩关闭保留为快捷方式。
5. 删除、重命名、沿用纹样的层级和确认反馈统一；删除取消不改变作品。
6. 导出预览页与月白内容场景统一，不再单独发明一套按钮样式。

验收：`320×568` 下所有底部操作完整可见；生成、失败、权限拒绝和保存成功都有明确反馈；信息抽屉最后一项不被安全区遮挡。

## 14. 分阶段实施计划

### 阶段 0：基线与 P0 修复

目标：先消除阻断体验的问题，并冻结可比较的当前基线。

1. 使用微信开发者工具保存所有核心页面和关键状态截图。

5. 为现有破坏性操作补齐禁用守卫和取消不变性检查。

退出条件：主流程没有被裁切的操作；设置无虚假承诺；关键控件可读可点；现有类型检查和测试通过。

### 阶段 1：设计基础设施

目标：建立新页面和旧页面都能复用的最小设计系统。

1. 新增 `styles/tokens.wxss`、`primitives.wxss`、`utilities.wxss`。
2. 建立颜色、字体、间距、圆角、阴影和动效 Token。
3. 建立本地图标资产和 `ui-icon`。

退出条件：基础示例页在浅/深场景中通过对比度、热区、减少动态和安全区验证；不引入第三方 UI 运行时。

### 阶段 2：内容页面迁移

目标：先用复杂度较低的页面验证设计语言。

迁移顺序：设置页 → 作品集 → 首页。

原因：设置页控件类型最完整，能验证列表、开关、单选和说明；作品集能验证导航、标签页、卡片、多选和空状态；首页最后调整可避免品牌方向在基础组件未稳定时反复修改。

退出条件：三页共享同一 Token 与导航；无局部同名变量重定义；主要交互语义完整；三档屏幕截图通过。

### 阶段 3：创作台样式治理与逐工序迁移

目标：在不破坏陶艺行为的前提下完成最大页面的结构化改造。

顺序：

1. 拆分样式文件和清理重复规则，不改变最终画面；
2. 统一顶栏、工序进度、底部操作和舞台基础；
3. 迁移制坯；
4. 迁移装饰与彩绘；
5. 迁移上釉；
6. 迁移高温烧制与低温烤花；
7. 统一 WebGL 兜底状态。

每个工序单独提交、单独截图、单独回归，不把 4523 行样式一次性替换。

退出条件：重复核心选择器收敛；关键文字和热区达标；七道工序、全屏、抽屉、短屏和减少动态全部验证；器物视觉尺度不变。

### 阶段 4：成品页与导出闭环

目标：让创作完成后的陈列、信息和导出体验与创作台连续。

1. 统一展台导航、标题、底部操作和信息抽屉。
2. 完成生成图、海报、分享和保存的加载/错误状态。
3. 统一预览页和相册权限反馈。
4. 验证沿用纹样、重命名和删除流程。

退出条件：所有窄屏操作完整可见；导出与权限路径可恢复；成品页和装饰工坊使用同一深色语义组件。

### 阶段 5：无障碍、性能与视觉回归

目标：将规范变成持续门禁，而不是一次性设计稿。

1. 全量语义与读屏检查。
2. Token 对比度、最小字号、硬编码色和 WXML 交互语义静态检查。
3. 三档屏幕、浅/深场景、空/满/错误/加载/禁用状态截图回归。
4. WebGL 主路径和兜底路径对比。
5. 真机触控、双指、长按、抽屉和安全区验证。
6. 低、中、高画质性能采样与 10 分钟稳定性测试。

退出条件：满足第 17 节验收标准，且没有以关闭检查、降低字号或删除状态反馈换取通过的例外。

## 17. 最终验收标准

### 17.1 一致性

- 所有页面的主操作、危险操作、导航、卡片、标签页和状态使用同一语义 Token。
- 页面不得重新定义 `--paper`、`--ink` 等同名但异义变量。
- 正式 UI 不再出现随机 Unicode 分类图标；箭头和操作图标来自统一图标集。
- 同类组件字号、热区、圆角和反馈一致，允许的明暗差异由主题 Token 提供。

### 17.2 可读性与可访问性

- 普通文字对比度不低于 `4.5:1`，大号文字和关键非文本控件不低于 `3:1`。
- 关键文字不小于 `24rpx`，操作文字不小于 `28rpx`。
- 标准触控目标推荐 `88rpx`，创作台最低 `80rpx`。
- 所有可点击 `view` 有正确角色和名称；选择、禁用和加载状态可被辅助技术理解。
- 选中、错误和进度均不只使用颜色表达。

### 17.3 布局与响应式

- `320×568`、`375×812`、`430×932` 三档视口无横向滚动、按钮裁切、系统胶囊重叠或安全区遮挡。
- 成品页三项导出/分享操作完整可见。
- 创作台七道工序无工具覆盖器物主要操作区；菜单开合和全屏不改变器物形状与视觉尺度。
- 文本放大、长作品名和双位数计数不会撑破卡片或 Grid。

### 17.4 交互

- 所有可交互元素至少有默认、按下、禁用/不可用及适用的选中、加载、成功、错误状态。
- 破坏性操作先确认，取消后数据与历史不变。
- 异步操作防重复提交，失败后可恢复重试。
- 减少动态在全部页面生效，触觉设置在全部触觉调用中生效。
- 设置页没有“看似可用但实际无效”的选项。

### 17.5 稳定性

- `npm run typecheck`、`npm test`、`git diff --check` 全部通过。
- 微信开发者工具无新增 WXML/WXSS 运行时错误。
- WebGL 主路径和兜底路径均能完成七道工序。
- 真机 10 分钟连续创作、抽屉开合、撤销重做和页面切换无持续内存增长或明显状态错乱。

## 18. 风险与控制

| 风险 | 可能表现 | 控制方式 |
| --- | --- | --- |
| 全局换色破坏单页气质 | 首页或工坊失去已有辨识度 | 使用语义迁移，不直接做全局查找替换；保留场景图片色 |
| 组件抽象过度 | 页面被迫塞入大量变体参数 | 先共享 Token 和样式，只抽取重复三次以上的稳定结构 |
| 创作台一次性重构 | 手势、历史、保存和布局同时回归 | 先等价拆文件，再逐工序迁移，每步单独截图和测试 |
| 提高对比度后面板过重 | 器物被大块实色面板压住 | 减少面板面积和信息密度，而不是降低文字对比度 |
| 扩大热区后顶栏放不下 | 控件重叠胶囊或标题 | 重排层级、合并低频项到更多菜单，不缩回热区 |
| 宋代美学变成符号堆砌 | 印章、宣纸、祥云到处出现 | 以比例、留白、天青和薄釉线为主，文化符号只在有语义处使用 |
| SVG 在基础库表现不一致 | 图标不显示或模糊 | 开发者工具和真机先验证；保留批量导出 PNG 方案 |
| 半透明表面在不同背景失效 | 同一文字在亮处看不清 | 按合成后最差背景做对比测试，并提供实色兜底 |
| 规范检查误伤业务色 | 釉色、泥料和 WebGL 色被强制替换 | 静态检查限定 UI 文件与属性，并设置明确白名单 |

## 19. 明确不采用的方案

- 不引入第三方大而全 UI 框架；项目页面数量和现有原生能力不需要这项复杂度。
- 不引入网络字体或未经授权的字体文件。
- 不将所有页面改成同一种米黄宣纸背景。
- 不用印章、祥云、书法和纹样铺满页面来证明“中国风”。
- 不把所有按钮做成胶囊，不把所有面板做成玻璃拟态。
- 不通过继续缩小文字和热区解决创作台密度问题。
- 不在 UI 统一过程中改写陶坯算法、作品 schema 或装饰持久化契约。
- 不以类型检查和单元测试代替微信开发者工具及真机视觉、WebGL 和触控验证。

## 21. 最终判断标准

改造完成后的“泥火青花”不应让用户首先注意到某个卡片用了宋体、某个角落放了印章，而应让用户自然感到：页面安静、器物突出、文字清楚、操作顺手，每一道工序都像在同一间温润的工坊中发生。

真正的一致性不是所有页面长得一样，而是无论用户处在月白内容页、暗色制陶台还是窑火展台，都能凭同一套颜色语义、文字层级、图标、间距和反馈方式立即理解界面，并把注意力留给自己正在完成的那件器物。
