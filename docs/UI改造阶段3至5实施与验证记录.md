# UI 改造阶段 3 至 5 实施与验证记录

> 实施日期：2026-08-29
>
> 对应基线：`docs/UI与交互规范及改造实施计划.md`
>
> 前置状态：阶段 0、1、2 已完成

## 1. 阶段 3：创作台样式治理与工序迁移

1. 将原 `studio.wxss` 拆分为 `base`、`shaping`、`decoration`、`glazing`、`firing` 五个职责明确的样式文件；入口只保留导入，核心顶栏规则仅在基础文件定义。
2. 七道工序统一为深色工坊语义：居中纯文字工序标题、保存状态、釉痕式七步进度、`80rpx` 工具热区、统一底部操作和舞台层级。
3. 制坯、装饰、上釉、彩绘、高温烧制、低温烤花及 WebGL 兜底状态完成迁移；装饰侧栏改用正式图标和“花卉 / 瑞兽 / 云水 / 几何”名称，保留约 `3:2` 的目录与内容比例。
4. 保留既有作品数据、历史、保存、相机和手势链。全屏仍禁用单指纹样移动，抽屉开合与全屏继续通过画布布局参数保护器物形状和视觉尺度。
5. 低、中、高画质除几何精度外，分别将 WebGL 渲染 DPR 限制为 `1 / 1.5 / 2`；减少动态同时覆盖工坊和窑火动效。

## 2. 阶段 4：成品页与导出闭环

1. 成品展台复用统一深色导航、标题和语义 Token；信息入口使用正式图标，信息抽屉提供明确关闭、内部滚动和月白内容主题。
2. 原生 WebGL 画布在信息抽屉或导出预览打开时隐藏，避免原生组件穿透；窄屏操作区可重排，作品图、海报、分享均有独立加载和防重复状态。
3. 作品图与纪念海报保留真实导出能力；生成失败显示行内错误并允许重试。相册保存区分权限拒绝与普通失败，预览不会因失败丢失。
4. 沿用纹样 / 完整复制、修改名称、删除作品均补齐进行中或失败反馈。删除先确认，取消不执行数据写入；复制成功后跳转失败可从首页继续进入已创建作品。

## 3. 阶段 5：持续门禁

新增并接入以下检查：

- 创作台样式拆分、核心选择器唯一性、最小字号、`80rpx` 热区和装饰区 `3:2` 布局；
- 正式操作不使用临时 Unicode 图标，图标名称与资产完整对应；                                                           
- 可点击 `view` 具备角色和名称，加载 / 禁用 / 错误 / 进度不只依赖颜色；
- UI 硬编码色、业务釉色白名单、Token 对比度和微信 WXSS 不兼容选择器；
- 成品页窄屏重排、信息抽屉、原生画布遮挡、导出恢复路径和减少动态；
- 三档画质的渲染 DPR 上限。

## 5. 尚需真机完成的最终验收

以下项目无法由本轮桌面模拟器和静态检查代替，发布前仍需执行：

1. 在真实 `320×568`、`375×812` 视口补齐逐状态截图；本轮已用 `max-width: 340px` 门禁覆盖短屏主操作重排，但不将其记为真机视觉通过。
2. 至少一台 iOS 和一台 Android 验证顶部胶囊、底部安全区、双指加入 / 离开、长按与滚动、抽屉开合以及真实触控热区。
3. 在低、中、高画质分别采样帧率、内存和温升，并完成 10 分钟连续创作、撤销重做、抽屉和页面切换稳定性测试。
